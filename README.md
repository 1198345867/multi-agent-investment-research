# 多 Agent 协同投研系统

基于共享黑板与自研顺序引擎的多 Agent 协同投研系统。输入一个 A 股标的与一个研究问题，系统会组织六个各司其职的 Agent 完成一次完整投研：拆解问题、采集数据、形成结论、自我质疑、回应质疑、撰写报告，最后交由评审把关，产出可逐条溯源的研究报告。

## 为什么做这个项目

单次 LLM 调用产出的投研结论有两个突出问题：一是数据来源不可追溯，二是没有人质疑它。本项目把「研究」拆成多个职责单一的环节，让结论在对抗与评审中被反复检验：

- **数据可追溯**：素材由工具直接搬运，不经模型改写，每条数据都带 `source` 与 `fetched_at`，报告中引用的证据可回查原始数据。
- **结论被质疑**：风控 Agent 在分析师出结论后专门挑刺，分析师必须逐条回应（采纳 / 部分采纳 / 反驳）并据此修订，结论保留全部版本，可直接对比演进。
- **交付有门槛**：评审 Agent 区分「阻断项」与「建议项」，只有阻断项才触发返工；评审通过才算定稿，始终不通过时以 best-effort 交付并明确标注。

## 工作流程

```
planner（规划）
   │  拆出 3-5 个核心问题 + 本轮要采集的数据项
   ▼
researcher（采集）
   │  按清单调用取数工具，把素材原文写入黑板（不经过模型）
   ▼
analyst（初版分析）
   │
   ├── 循环 2 轮 ────────────────────────────┐
   │     risk（风控质疑）  →  analyst（逐条回应并修订）
   │                                         │
   ◀─────────────────────────────────────────┘
   ▼
writer（撰写初稿）
   │
   ├── 循环至多 3 轮 ────────────────────────┐
   │     reviewer（评审）  →  未通过则 writer（带阻断项修订）
   │                      →  通过则定稿
   ◀─────────────────────────────────────────┘
   ▼
report（报告）+ 跨轮记忆 + 历史存档
```

轮数由 `engine.py` 顶部的常量控制：`DEBATE_ROUNDS = 2`、`MAX_REVIEW_ROUNDS = 3`。

## 架构：共享黑板 + 显式编排

**共享黑板（`state.py`）** 是所有 Agent 交换信息的唯一载体。各 Agent 之间不做两两直接通信，因此不存在消息风暴与状态不一致。黑板按分区划分归属，每个分区只有一个写入者、其余只读：

| 分区 | 写入者 | 内容 |
| --- | --- | --- |
| `plan` | planner | 本轮核心问题与数据采集清单 |
| `materials` | researcher | 采集到的素材原文 |
| `analyses` | analyst | 结论的每个版本（初版 + 各轮修订） |
| `challenges` | risk | 风控质疑 |
| `rebuttals` | analyst | 对每条质疑的回应与处置 |
| `draft` / `report` | writer / 引擎 | 草稿与定稿报告 |
| `reviews` | reviewer | 每轮评审结果 |
| `metrics` | 引擎 | 每个环节的耗时与 token 消耗 |

**流程引擎（`engine.py`）** 把各 Agent 按固定顺序串成一次研究。编排逻辑用代码直述而不引入图引擎：本流程是固定主链加两条回边，直写比用图描述更易读、也更好改。

六个 Agent 都是纯函数（`(state) -> None`），只读写黑板、不发请求、不互相依赖，因此单个 Agent 可以独立替换与测试。

```
│   ├── analyst.py       分析：初版结论与逐轮修订

│   └── reviewer.py      评审：阻断项与建议项

│   ├── data.py          akshare 取数（行情、财务、概况、新闻、代码反查）

│   └── cache.py         取数结果按 (标的, 数据项, 日期) 落盘缓存
├── memory/
│   ├── store.py         跨轮持久记忆（摘要级）

├── cache/               运行时生成，已 gitignore
└── memory/data/         运行时生成，已 gitignore
```

## 快速开始

环境要求：Python 3.12。

```bash
pip install -r requirements.txt
```

配置模型服务（OpenAI 兼容协议，默认接入 AGICTO 聚合平台）：

| 环境变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `LLM_API_KEY` | 是 | 回退读取 `AGICTO_API_KEY` | 模型服务密钥 |
| `LLM_BASE_URL` | 否 | `https://api.agicto.cn/v1` | 接口地址，可指向任意兼容厂商 |
| `LLM_MODEL` | 否 | `qwen-plus` | 模型名 |

PowerShell 下设置：

```powershell
$env:LLM_API_KEY = "你的密钥"
```

命令行运行一次研究：

```bash
python main.py 600519
python main.py 600519 "分析茅台当前是否具备投资价值"
python main.py 600519 --user alice
```

启动可视化界面：

```bash
streamlit run app.py
```

界面支持按公司名称反查代码、运行期间实时刷新协同轨迹、随时中止、查看每个环节的耗时与 token 消耗、评审收敛度图表、下载 Markdown 报告，以及只读回看跨轮记忆与历史存档。

## 关键设计说明

- **中止不留痕**：`engine.run` 在每个环节开始前检查一次中止判据，命中即抛 `RunCancelled` 结束本轮，且不写记忆、不存档——中止的轮次当作没发生过，不会留下半成品污染跨轮记忆。
- **可复现指流程而非结论**：编排顺序完全确定，每次运行的流转一致，`trace` 逐轮记录可核对；LLM 输出本身带随机性，因此保证的是流程可复现，不是结论逐字可复现。
- **不做重试与降级**：`llm.chat_json` 用 `response_format=json_object` 约束输出形态，再由 pydantic 严格校验；校验不通过直接抛错，让问题暴露而不是被掩盖。
- **规划必须「数据可回答」**：`researcher.py` 里的 `DATA_CAPABILITIES` 会注入规划 Agent 的提示词，让它知道数据能提供什么，从而不提这些数据回答不了的问题，避免「报告如实说明数据缺失、却被审校判为漏答」的死循环。
- **取数缓存**：行情财报类数据当天不变，缓存按 (标的, 数据项, 日期) 落盘，跨轮研究同一标的直接命中。缓存只读不删，需强制刷新时手工删除 `cache/` 目录。
- **记忆按用户隔离**：跨轮记忆以 `memory/data/<user_id>.json` 存储，只存摘要不存全文，避免记忆库无限膨胀；`--user` 参数用于隔离不同用户。

## 技术栈

Python 3.12、Pydantic v2（数据结构与校验）、akshare（A 股数据源）、pandas / numpy、OpenAI 兼容接口（默认 qwen-plus）、Streamlit（界面）。
